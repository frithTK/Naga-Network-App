# Совместимость протоколов: подробные шаги

Основание и текущие ограничения: [общий план](PROTOCOL_COMPATIBILITY_PLAN.md).
Частично выполненная работа и результаты проверок записываются в
[журнале выполнения](PROTOCOL_COMPATIBILITY_PROGRESS.md). Отмечать `[x]`
только при наличии полного результата шага; для недоступного устройства,
серверной конфигурации или проверки записывать `UNAVAILABLE` и причину.

## Зависимости и учёт результатов

- P0 определяет реальные входы и версии. Синтетические регрессии и независимые
  исправления импорта можно начинать без доступа к серверу; совместимость с
  сервером и приёмка без реальных данных остаются открытыми.
- P1 исправляет представление узлов, P2 добавляет работающий olcRTC runtime,
  P3 — обработку AWG. Этапы могут развиваться независимо после P0, но для
  выдачи реальной подписки должны быть согласованы с P4.
- Системная интеграция P2 на macOS зависит от готовности helper и базового
  datapath из [этапов M03–M05](MACOS_IMPLEMENTATION_STEPS.md). Работу над
  olcRTC выполнять совместно с M06.03–M06.05, а не ждать их завершения как
  предварительного условия. Проверка общего парсера и сборки не закрывает
  эту зависимость. P5 следует за соответствующими изменениями и проводится
  для каждой заявленной платформы.
- Для каждого шага записывать ссылку на изменение и тест или наблюдение;
  результаты parser/build/component/device/production хранить раздельно.
  Реальные ключи, токены, профили, приватные адреса и идентификаторы комнат
  не включать в fixtures, логи, отчёты или CI.
