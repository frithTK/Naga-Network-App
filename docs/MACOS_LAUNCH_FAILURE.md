# Отказ первого запуска на Mac

2026-10-19 пользователь сообщил, что Finder показывает «The application “Naga Network” can’t be opened», без возможности перейти к встроенной проверке. Точная версия macOS и установленный путь запрошены, но пока не получены. По одному этому сообщению нельзя однозначно установить причину на устройстве.

## Подтверждённые результаты

Проверен именно опубликованный DMG `macos-dev-1.2.9-check1`, source `6f4e2bf382d2d21d293e0cb2b6de5d9abc233506`, SHA-256 `a49a532785649ed871bbaebd04709c0ea49eedfcc116400b299eaee9bdf13d26`.

- Главный executable имеет права 0755, архитектуру ARM64 и deployment target 14.0. Библиотеки содержат ARM64, framework symlinks разрешаются.
- [Run 39207970950](https://github.com/frithTK/Naga-Network-App/actions/runs/39207970950) скопировал приложение из опубликованного DMG и открыл его через LaunchServices на **macOS 14 и 26**. На обеих средах подтверждены окно, дочерний backend, пять секунд стабильной работы, штатный выход и остановка backend.
- Это **не** проверка браузерного карантина: `curl` не воспроизводит метаданные скачивания Safari. Соответствующий результат GUI smoke явно записан как `quarantine_acceptance: UNAVAILABLE`.
- `syspolicy_check distribution` на обеих ОС отклонил пакет: `Notary Ticket Missing`, `Internal Xprotect Error`; macOS 26 дополнительно явно сообщает `Adhoc Signed App` и рекомендует Developer ID.
- Проверки старого CI проверяли подпись и packaged backend, но не запуск GUI и не distribution assessment. Прохождение старого CI не подтверждало установку скачанного приложения.

Недостающая нотариализация подтверждена. `Internal Xprotect Error` не позволяет без дополнительных данных назвать конкретную причину отказа на пользовательском M2. В частности, успешный локальный запуск не доказывает возможность штатно разрешить запуск браузерной копии.

## Изменения в упаковке и CI

Из Flutter engine удаляется внешний `LC_RPATH /usr/local/lib/.`, а из App.framework — несуществующие относительные каталоги поиска. Оставляются существующие пути внутри bundle и системные пути. После правки Mach-O framework подписывается заново до внешнего app. Права всех Mach-O нормализуются до 0755. Это исправление переносимости, а не доказательство устранения ошибки на пользовательском Mac.

`check-app.py` проверяет `LC_RPATH`, executable permissions и записывает реальный вердикт `syspolicy_check` отдельно от strict codesign. Обычная сборка теперь действительно открывает GUI через LaunchServices, проверяет окно/backend и завершение. Для опубликованного пакета можно отдельно запустить workflow с `release_tag` и `release_sha256`: он проверяет точные скачанные байты на macOS 14/26, не пересобирает приложение и не регистрирует системную службу.

## Разовый локальный тест доверенной сборки

Если пользователь сознательно проверяет именно эту сборку проекта, после копирования Naga в `/Applications` можно удалить метку карантина только у её bundle и открыть приложение:

```sh
xattr -dr com.apple.quarantine "/Applications/Naga Network.app" && open "/Applications/Naga Network.app"
```

Это обход проверки скачанного файла для локальной разработки. Он не добавляет Developer ID, не заменяет нотариализацию и не считается готовым пользовательским установщиком. Если команда сообщает ошибку, нужен её текст; успешное выполнение также ещё не подтверждает работу VPN/helper.

## Штатная поставка

Для обычного распространения требуется Developer ID Application, подпись всего вложенного code, hardened runtime и notarization/stapling итогового пакета с отдельной проверкой установки скачанной копии. Доступ к сертификату и notarization не предоставлен. Эти входы остаются открытыми; новая ad-hoc сборка не объявляется исправленным пользовательским установщиком.

Основания: [Apple: Developer ID](https://developer.apple.com/developer-id/), [Apple: Resolving Gatekeeper Problems](https://developer.apple.com/forums/thread/706379). Пользовательский сценарий: [быстрая проверка](MACOS_QUICK_CHECK.md).
