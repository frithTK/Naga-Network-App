# Проверка диагностической службы на M2

Для обычной проверки используйте кнопку **«Проверить Mac»** в основном приложении: [три шага](MACOS_QUICK_CHECK.md). Этот документ предназначен для последующих инженерных проверок перезагрузки, замены и возврата версий; передавать весь сценарий обычному пользователю не требуется.

Цель: проверить реальную установку `SMAppService`, XPC и замену приложения на macOS 14+. Пробник не является VPN-клиентом. Его helper умеет только возвращать build, версию протокола, UID и PID; он не меняет DNS, маршруты и файлы пользователя.

Обе версии имеют **ad-hoc подпись**. Возможность регистрации с такой подписью пока не подтверждена. Отказ macOS с записанным кодом ошибки — полезный результат проверки. Версии с Developer ID проверяются отдельно после появления signing identity.

## Подготовка

1. Скачать [ZIP версии A](https://github.com/frithTK/Naga-Network-App/releases/download/macos-dev-1.2.9-b14/NagaServiceProbe-A-macos-arm64.zip), [ZIP версии B](https://github.com/frithTK/Naga-Network-App/releases/download/macos-dev-1.2.9-b14/NagaServiceProbe-B-macos-arm64.zip) и [SHA256SUMS.txt](https://github.com/frithTK/Naga-Network-App/releases/download/macos-dev-1.2.9-b14/SHA256SUMS.txt). Файлы опубликованы в [тестовом релизе](https://github.com/frithTK/Naga-Network-App/releases/tag/macos-dev-1.2.9-b14) и доступны без входа в GitHub. Исходный commit `87bcd7b5fd66cb58cc8ff64417356ebac4acb7f9`.
2. Сохранить оба ZIP. Распаковывать их по очереди или в отдельные каталоги A/B: приложения имеют одинаковое имя и предназначены для последовательной установки.
3. Записать версию и build macOS через «Об этом Mac» → сведения о системе.
4. При желании проверить checksum в Терминале: `shasum -a 256 <путь-к-ZIP>`; сравнить с соответствующей строкой `SHA256SUMS.txt`.

## Версия A: регистрация и XPC

1. Распаковать **ZIP из A**, скопировать `Naga Service Probe.app` в `/Applications`, открыть оттуда.
2. Если Gatekeeper блокирует запуск скачанного ad-hoc приложения, зафиксировать сообщение. Для собственного тестового приложения можно использовать штатное «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть», если этот пункт доступен. Если запуск недоступен, остановить проверку и передать сообщение; отключать Gatekeeper целиком не требуется.
3. Убедиться, что заголовок показывает **A**. Нажать «Зарегистрировать» и записать статус или полную ошибку `domain / code`.
4. Если macOS запрашивает разрешение, сначала проверить отказ: записать результат, затем повторить регистрацию. Открыть настройки кнопкой приложения и разрешить службу, если macOS предлагает такое действие.
5. Нажать «Обновить статус», затем «Запросить состояние helper». Успех: JSON содержит `"build":"A"`, `"protocol_version":1`, `"euid":0`. Сохранить ответ целиком. Отдельно отметить таймаут или ошибку XPC.
6. Закрыть приложение, открыть повторно и снова запросить состояние. Затем перезагрузить Mac, открыть приложение и повторить запрос; записать результат каждого шага.
7. Нажать «Удалить регистрацию службы», обновить статус и убедиться, что он сообщает об отсутствии регистрации. Повторный запрос helper должен завершиться ошибкой/таймаутом. Повторно зарегистрировать A и проверить ответ.

## Версия B: замена и возврат

1. В A удалить регистрацию службы и убедиться в отсутствии регистрации. Закрыть приложение через `⌘Q`.
2. Распаковать **ZIP из B**, скопировать приложение в `/Applications` с заменой A. Открыть установленную копию; заголовок должен показывать **B**.
3. Зарегистрировать службу, при необходимости выдать разрешение, запросить состояние. Успех: `"build":"B"`, `"protocol_version":2`, `"euid":0`.
4. Если ответила A или приложение сообщает о несовместимой версии, сохранить ответ и остановить замену: это означает, что lifecycle helper требует доработки. Не считать отображение заголовка B доказательством обновления службы.
5. Для проверки возврата удалить регистрацию B, закрыть приложение, заменить его сохранённой A. Повторить регистрацию и запрос: ожидаются A / 1 / UID 0.
6. После проверки **удалить регистрацию**, убедиться в соответствующем статусе, закрыть приложение. Только после этого удалить приложение из `/Applications`.

Переход с живой службой без unregister и автоматическое обновление здесь не проверяются. Контракт реального helper, связь с Go backend и полномочия клиента относятся к следующим этапам; проверка идентификатора ad-hoc подписи в этом пробнике подтверждает только ограниченный диагностический сценарий.

## Что передать по результатам

```text
Mac / macOS version / build:
Actions run / исходный commit:
Первое открытие / сообщение Gatekeeper:
Регистрация A, включая отказ и повтор (status или domain / code):
Ответ helper A:
Ответ после повторного открытия / reboot:
Удаление регистрации и повторный запрос:
Замена A → B, ответ helper:
Возврат B → A, ответ helper:
Финальное удаление регистрации:
```

В результатах нет необходимости прикладывать VPN-профили, пароли или токены. Если этап не прошёл, достаточно его точной ошибки; последующие зависимые шаги оставить непроверенными.
