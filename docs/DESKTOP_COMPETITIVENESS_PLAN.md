# План доработок Naga Network по итогам сравнения клиентов

Дата: 2026-11-21. База сравнения: релиз 1.2.10 для Linux и Windows и код ветки
`feat/macos-arm64-bootstrap` на `30f4832`. Исправление ложного предупреждения
при сохранении политики на момент проверки находится в рабочей копии.
Сравнение опирается на код, документацию и наблюдения пользователя. Для скорости,
доли успешных подключений и восстановления нужны прогоны на одном стенде.

## Подтверждённые ограничения

| Область | Что уже есть в Naga | Что осталось сделать |
|---|---|---|
| Форматы импорта | HTTPS-подписки с sing-box JSON или конвертом Naga, AWG `.conf` и отдельные варианты olcRTC. | Hiddify и v2rayN читают списки URI. С User-Agent сервиса Naga сторонняя подписка вернула HTTP 200 и Base64-список из 32 VLESS и одного Hysteria2. Предпросмотр исходного тела вернул HTTP 422. С браузерным User-Agent загрузчика Naga тот же адрес на проверенном пути вернул 404. У 15 VLESS есть `fm` (Xray FinalMask). [Форматы Hiddify](https://hiddify.com/app/URL-Scheme/) · [Соглашение о ссылках VLESS](https://github.com/XTLS/Xray-core/discussions/716) · [Генерация `fm`](https://github.com/MHSanaei/3x-ui/blob/main/frontend/src/lib/xray/inbound-link.ts) |
| Управление профилями | Предпросмотр, сохранение URL, обновление и проверка движком. | Подтверждённый импорт останавливает активную сессию даже при добавлении отдельного профиля. Сохранение сторонней подписки, применение обновления к ней и выбор её узла должны иметь отдельные пользовательские действия. [Импорт в control](../core/control/server.go#L1088) |
| Проверка узлов | Ранние результаты, прогресс и отмена. Проверка AWG различает рукопожатие и HTTPS и может использовать резервную цель. | Обычные sing-box узлы проверяются по фиксированному URL. Karing даёт менять его. Задержка контрольного HTTPS-запроса не объясняет качество UDP, а пинг через разные цели нельзя сравнивать напрямую. [Настройки Karing](https://karing.app/en/app-manual/settings) · [Реализация замеров Naga](LATENCY_IMPLEMENTATION.md) |
| Автовыбор | До трёх основных кандидатов, ранжирование по типу сети и отдельная группа TUIC. | Hiddify для профиля своей панели описывает проверку всех конфигураций. Для нашего короткого списка нужно измерить, как часто пригодный узел остаётся за его пределами и сколько стоит расширение списка. [Автовыбор Hiddify](https://hiddify.com/app/How-to-use-Hiddify-app/) · [Политика Naga](../core/policy/policy.go#L13) |
| Соединения и DNS | Активный узел, журнал, агрегированные счётчики, сводка загруженной конфигурации. | FlClash и Clash Verge Rev дают контекст по отдельным соединениям. Naga нужна связь процесса, правила, выхода и фактических ответов, включая UDP и DNS. [FlClash](https://github.com/chen08209/FlClash/blob/main/.agents/architecture.md) · [Clash Verge Rev](https://github.com/clash-verge-rev/clash-verge-rev/blob/dev/src/locales/zh/connections.json) |
| Маршрутизация и DNS | Готовые режимы маршрутизации приложений, локальной сети и доменов, правила подписки. | Clash Verge Rev подробнее управляет правилами и DNS глобально и для отдельных подписок. В Naga порядок и эффективное правило трудно прочитать из интерфейса. [Расширения Clash Verge Rev](https://www.clashverge.dev/guide/extend.html) |
| Подключение и восстановление | Контроль состояния, автоперевыбор узла, перезапуск движка и восстановление ряда настроек при сбое. | Один запуск Hysteria2 занял 22,6 с. Сохранение политики заняло 32,3 с и вышло за прежний клиентский бюджет 10 с. Обработчик класса сети пропускает смену Wi-Fi → Wi-Fi. Стабильность AWG и игрового UDP на системном TUN требует стенда. [Смена класса сети](../core/control/runtime_probe.go#L805) · [Стенд AWG](AWG_IMPLEMENTATION_STEPS.md) |
| Трафик при сбое | Действующие механизмы восстановления зависят от ОС и режима трафика. | Mullvad документирует блокировку трафика и политику Lockdown. Для Naga нет общей проверенной гарантии блокировки при потере туннеля, включая IPv6 и DNS. [Mullvad](https://mullvad.net/en/help/using-mullvad-vpn-app) · [Аудит Naga](CODE_REVIEW_REPORT.md#L374) |
| Ядра и платформы | Встроенный sing-box, отдельные AWG и olcRTC. Для Linux/Windows выпущены пакеты 1.2.10. | v2rayN поддерживает Xray и несколько других ядер. У Naga нет эквивалентного режима для несовместимых функций Xray, включая FinalMask без проверенного соответствия. macOS VPN остаётся экспериментальным, поддержку на мобильных нужно проверять по фактическим сборкам. Установка своего сервера, как в AmneziaVPN, относится к отдельному продуктовому сценарию. [Ядра v2rayN](https://github.com/2dust/v2rayN/wiki/List-of-supported-cores) · [AmneziaVPN](https://github.com/amnezia-vpn/amnezia-client) · [macOS vpn2](MACOS_VPN_TEST.md) |

Первый обходной вариант содержал два узла. После реализации общего импорта
проверка из Linux AppImage сохранила исходный URL и 17 уникальных узлов.
Повторное обновление профиля прошло. Один узел совпал с уже добавленным,
15 требуют Xray FinalMask. Новое ядро использует заданный в подписке
`hellochrome_120` без подмены отпечатка. Проверка проводилась с отдельным
локальным сервисом и хранилищем.

## P0. Сторонние подписки и добавление профиля

- [x] Добавить тесты для смены User-Agent после HTTP 404, Base64-списка,
  VLESS с `fm`, Hysteria2, `firefox` и `hellochrome_120`. Фикстуры используют
  тестовые адреса и ключи.
- [x] Вынести распознавание формата в общий путь control для предпросмотра,
  импорта и обновления. Сохранить прямую загрузку и загрузку через работающий
  VPN. Воспроизвести выбор User-Agent на обоих путях; ограничить повторные
  попытки и сохранить проверки HTTPS, редиректов, адресов и размера ответа.
  Отличать HTTP-ошибку, HTML, неизвестный формат и неподдерживаемые параметры.
- [x] Принимать одиночные URI, построчные списки и стандартный/URL-safe Base64.
  Поддержаны варианты VLESS, VMess, Shadowsocks, Trojan, Hysteria2 и TUIC,
  а также поддерживаемые встроенным ядром узлы из Clash YAML. Предпросмотр
  показывает, что профили Clash используют маршрутизацию и DNS Naga.
  Обёртки Hiddify, Clash, v2rayNG и sing-box раскрываются до исходного HTTPS URL.
- [x] Показывать в предпросмотре число пригодных, несовместимых и повреждённых
  узлов. Сохранять URL и метаданные для обновления. Устойчивый ID узла должен
  переживать смену порядка и имени. Повреждённое или несовместимое обновление
  не заменяет пригодную копию и не меняет строгий выбор на другой узел.
- [x] Добавление отдельного профиля сохраняет текущий активный профиль и VPN.
  Для повторного добавления того же URL использовать сценарий обновления,
  включая проверку выбранного узла и откат при ошибке применения.
- [ ] Добавить обработку Clash proxy-providers и совместимые правила
  преобразования. Расширять транспортные варианты по тестовым фикстурам.
  Для Xray FinalMask требуется отдельное подтверждение соответствия или
  поддержка Xray. Сейчас такие узлы отражаются в счётчике причин пропуска.

Готово, когда одинаковый формат даёт одинаковый результат в preview, import и
refresh, частичный импорт требует осознанного подтверждения, а добавление
соседнего профиля не прерывает сессию. Для обнаруженного формата отдельно
подтверждены все поддержанные варианты и понятная причина для `fm`.

## P0. Достоверный прогресс подключения

- [x] Увеличить ожидание сохранения, убрать повторный выбор в «Авто» и показывать
  этапы запуска туннеля в Flutter по состоянию локального сервиса.
- [ ] Показать отдельные этапы рукопожатия, отмены и изменения политики.
  Сверять фактический результат после разрыва связи.
- [ ] Задать отдельные бюджеты этапов и общий бюджет. Проверить отмену,
  повторный запуск, поздний ответ, конфликт Start/Stop/Select, изменение
  профиля и откат. При ручном выборе измерить, насколько запуск зависит
  от соседних узлов и фоновых проверок.
- [ ] Показывать состояние туннеля отдельно от доступности контрольной цели.
  В деталях замера указывать источник, цель, время и состояние актуальности.
  Сохранять явный статус при смене узла или сети.

Готово, когда медленное успешное действие даёт подтверждённый финал, а
потеря локального сервиса и ошибка проверки внешнего доступа видны отдельно.

## P1. Маршрут приложения и диагностика UDP, DNS, HTTPS

- [x] Добавить снимок активных соединений sing-box в Flutter. Видны процесс
  при наличии данных, TCP/UDP, назначение, цепочка, правило и счётчики.
  Покрыт разбор ответа ядра. Встроенный sing-box также пропустил двусторонний
  UDP через локальный SOCKS и отобразил оба счётчика в API соединений.
- [ ] Подтвердить полноту полей на системном TUN и в системном прокси под
  реальной нагрузкой и отдельно на каждой заявленной платформе.
- [ ] Добавить независимую проверку DNS, TCP/HTTPS и двустороннего UDP на
  контрольном стенде. Сопоставить клиентский результат с полученными
  пакетами и реальным выходом. Для Dota отдельно проверить вход в
  тренировочный матч с AWG и Hysteria2, входящие игровые пакеты и сохранение
  соединения. Для Codex проверить факт HTTP-ответа по выбранному выходу.
  HTTP 403 сохранить как отказ сервиса, причину устанавливать отдельно.
  TUN сам по себе не видит HTTP-статус внутри TLS. Использовать статус,
  предоставленный приложением, или отдельную HTTPS-проверку.
- [ ] Сделать ограниченный по объёму отчёт по выбранной сессии: агрегаты,
  этап, причины и время. Исключить ключи, токены, ссылки подписок и
  содержимое пакетов. Проверить стоимость наблюдения на большом списке
  соединений.

Готово, когда можно отличить неправильное правило, отсутствие UDP-ответа,
проблему резолвера и отказ сайта без чтения полного журнала sing-box.

## P1. Замеры и переход между сетями

- [ ] Для каждого движка проверить единый смысл результата и возможность
  выбора HTTPS-цели, отдельно для ручного замера и проверки доступности.
  Сравнивать значения только для сопоставимых целей, режимов и прогрева.
  Сохранить прогресс, отмену и защиту от результата устаревшего задания.
- [x] Добавить запасную тройку перед TUIC. После первого успешного результата
  давать группе 350 мс на оставшиеся ответы. Подтвердить порядок групп тестом.
- [x] Учитывать идентификатор активного подключения NetworkManager и
  перевыбирать по существующей политике при смене Wi-Fi → Wi-Fi.
  Подтвердить событие в синтетическом тесте.
- [ ] Измерить время запуска с быстрым узлом за пределами первой тройки.
  Проверить на устройстве Wi-Fi → Wi-Fi, Ethernet, VPN поверх другого VPN,
  sleep/wake и краткий разрыв. Сверить привязку UDP AWG после смены сети.
- [ ] Сравнить Naga с AmneziaVPN на одном AWG-профиле, а с Karing или FlClash
  на одном Hysteria2-узле. Зафиксировать холодный/тёплый запуск, время до
  подтверждённого пользовательского трафика, первый/последний результат
  массового замера, медиану, p95, долю отказов и время восстановления.
  Для p95 ключевого сценария собрать не менее 30 прогонов на вариант;
  тайм-ауты учитывать в доле отказов.

Готово, когда для переходов установлено фактическое время восстановления,
а различия в скорости подтверждены сопоставимыми прогонами.
Подробные сценарии приведены в [плане AWG](AWG_IMPLEMENTATION_STEPS.md).

- [ ] Перед выпуском прогнать синтетические тесты, собрать пакеты и проверить

  профилей и возврат к предыдущей версии.

Задачи по протоколам ведутся вместе с [планом совместимости](PROTOCOL_COMPATIBILITY_PLAN.md).

зафиксировать поддерживаемые VPS, протоколы и обслуживание.
