# Пошаговая разработка Naga Network для macOS

Версия 2, 2026-10-18. Исправлена по результатам [проверки плана](MACOS_PLAN_REVIEW.md). Исполнение начато; доказательства выполнения приведены в [ходе разработки](MACOS_IMPLEMENTATION_PROGRESS.md).

Это детализация [основного плана](MACOS_DEVELOPMENT_PLAN.md). Сохраняются 58 исходных ID; добавлены M00.07, M03.07 и M04.07. Цель: macOS 14+, ARM64, MacBook M2, установка обычного приложения через DMG. Проверенные исходные факты, ограничения подписи и ссылки на документацию приведены в основном плане.

Каждый чекбокс обозначает отдельное действие с результатом. Родительская задача закрывается после всех применимых подшагов и проверки её критерия «Готово». Для шага, которому нужен недоступный Mac, сертификат или тестовый сервер, записываются причина `UNAVAILABLE` и необходимое условие проверки. Такой шаг остаётся открытым.

Новые имена файлов ниже обозначают предполагаемое размещение реализации. Структуру helper и bridge фиксирует M00.06. Прототипы из M00 предназначены для проверки предпосылок; их перенос в поставляемый код проходит этапы M01–M07.

Очередь первой beta: сборочные входы **M00.01/M00.02 → M01/M02**, подтверждённый install/auth path **M00.04–M00.06 → M03**, далее **M04 → M05 → тестовый M07 → M08**. Прототип M00.07 обязателен до заявления о проверенной замене app/helper, но не до первого открытия UI. Расширение движков: **M06 → повтор M07/M08 для изменённых компонентов**. Подписанный пакет заново собирается внутри M09.01 теми же scripts M07, затем проходит M09.02; зависимости M07 от M09 нет. Автообновление M09.03–M09.05 имеет отдельный критерий готовности.

Для проверяемых отчётов использовать `docs/testing/macos/<build-id>/`: release manifest, результаты сценариев и обезличенные материалы. `build-id` задаётся до упаковки как version + commit + run ID; окончательный digest DMG добавляется во внешний release manifest и отчёт. Сырые логи, пакеты, ключи и профили находятся вне отслеживаемых каталогов. Встроенный build manifest не содержит хеша включающего его DMG.

## Как отмечать выполнение

Для каждого выполненного подшага сохранить ID, commit реализации, стенд и ссылку на результат. Родительский пункт `Mxx.yy` в основном плане отмечается после завершения дочерних действий и его приёмочного критерия. Повторная проверка после изменения артефакта получает новую запись с актуальным SHA-256.

Результаты DEV и SIGNED ведутся отдельно. Например, успешная dev-замена helper в M00.07 не закрывает подписанную ветвь; отсутствие сертификата оставляет её открытой, но не отменяет подтверждённый DEV-результат. Готовность канала определяется его обязательными строками матрицы M08.01, а не общим числом отмеченных чекбоксов.

Для первой beta обязательны install/auth/TUN результаты M00, M01–M05, тестовый M07 и заранее зафиксированная матрица M08. Сценарий замены app/helper допускается к объявлению после M00.07 и M07.06. Задачи M06 закрываются по каждому движку до объявления его поддержки. Подписанная ручная поставка проходит M09.01/M09.02/M09.06 и проверку ручного обновления; автоматическая — дополнительно M09.03–M09.05.
