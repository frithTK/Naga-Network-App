# Первая проверка VPN на Mac

Экспериментальный этап M00.03/M00.05: приложение соединяет пользовательский backend
с root-службой и закреплённым sing-box. Успешная сборка не подтверждает передачу
трафика. Проверка на физическом Mac остаётся обязательной.

Требуются Apple Silicon, macOS 14+ и рабочий профиль VLESS/Reality. macOS 26.2 —
первый физический стенд; ранее на нём проверена отдельная диагностическая служба.
Системный proxy, AmneziaWG, olcRTC и автоматическое обновление не входят в этот этап.

1. Скачайте экспериментальный DMG через Safari/Chrome, отключите VPN и завершите
   прежнюю Naga через Command-Q. Перенесите приложение в «Программы» и откройте его.
2. Импортируйте один рабочий профиль, выберите его узел и режим **TUN**.
3. Нажмите подключение. При первом запуске разрешите службу Naga в открывшихся
   настройках фоновых элементов. Вернитесь в приложение; при истечении ожидания
   повторите подключение после разрешения.
4. Проверьте открытие сайтов и внешний IP. Сверьте ожидаемый IP VPN с выбранным
   узлом и действующими правилами обхода.
5. Отключите VPN. Проверьте, что сайты снова открываются обычным способом.
   Повторите подключение/отключение, затем завершите приложение через Command-Q.
6. Передайте версию macOS, результат подключения, изменения IP, состояние сети
   после отключения и текст ошибки, если она возникла. Профили и токены не нужны.

Терминал для проверки не нужен. Кнопка «Проверить Mac» продолжает проверять
отдельную временную диагностическую службу и не доказывает готовность VPN.
Разрешение запуска ad-hoc приложения и разрешение фоновой службы — разные шаги;
сведения о первом открытии приведены в [инструкции](MACOS_QUICK_CHECK.md).

Root-служба принимает ограниченную конфигурацию, выбирает свободный utun и владеет
своими маршрутами и временным DNS-ключом. Backend передаёт локальные rule-set как
встроенные правила; root не читает выбранные пользователем пути. Клиент XPC
проверяется по CDHash текущего bridge, engine — по SHA-256. Привилегированный API
разрешает статистику, замеры и выбор узла. Потеря bridge/heartbeat запускает cleanup,
а runtime содержит watchdog родительского helper.

До device acceptance остаются открытыми: фактические TCP/UDP/DNS/IPv6, конфликт
с другим VPN, отказ и отзыв разрешения, смена сети, sleep/wake, принудительное
завершение компонентов и замена уже зарегистрированной VPN-службы. Журнал текущего
прототипа не является завершённым механизмом восстановления после всех сбоев.
