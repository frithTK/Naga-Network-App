# Эксперимент с маршрутизацией olcRTC на Linux

Это исследовательский тест для исходников olcRTC commit
`b8a6e12e3e3afb0666e38f9668c7d81d8aff948f`. Текущая сборка приложения его не
использует. Эксперимент подключает встроенный upstream socket protector и ставит
на защищённые сокеты Linux `SO_MARK`. Если метку задать не удалось, создание
сокета отклоняется. Метка `0` и некорректные значения запрещены.
В эксперименте `NAGA_OLCRTC_REQUIRE_MARK=1` дополнительно запрещает запуск
при отсутствии метки; вызывающий процесс обязан сам задать эту опцию.

Экспериментальный Linux x86-64 бинарник можно собрать без изменения checkout
и установленного приложения:

```sh
bash scripts/olcrtc/build-linux-candidate.sh /path/to/disposable-olcrtc-checkout /tmp/olcrtc-mts-candidate
```

Сборка проверяет commit, использует Go overlay и не перезаписывает готовый
файл. Это исследовательский бинарник: без переменной метки hook не включён,
policy routing не настроен, поэтому для системного VPN он пока непригоден.

Команда ниже требует Linux с доступными user/network namespaces, `iproute2`,
`setpriv`, Go и **отдельный одноразовый checkout** указанного commit с уже
доступными зависимостями:

```sh
bash scripts/olcrtc/test-linux-mark.sh /path/to/disposable-olcrtc-checkout
```

Скрипт временно копирует два файла в исходники CLI и удаляет их при выходе.
Если файлы с такими именами уже есть, скрипт прекращает работу. Временный CLI
удаляется. Правила `ip` создаются только внутри нового network namespace; в
нём нет доступа к сети хоста. Тест проверяет недоступность TCP без метки,
работу защищённого TCP и UDP-адаптера Pion по IPv4/IPv6, транспорта DNS по
IPv4, а также явный
отказ сокета после удаления необходимых capabilities. DNS проверяется как
пересылка пакета через upstream resolver, а не как полноценный публичный DNS.

Перед использованием в приложении ещё необходимы: безопасное выделение и
освобождение метки, таблицы и приоритета без конфликтов с чужими VPN;
проверка всех путей сигнализации и WebRTC; поддержка IPv4/IPv6 и смены сети;
создание и удаление только принадлежащих приложению правил с восстановлением
после ошибки или падения; проверка реального TUN и старых серверов. Успех этого
эксперимента не подтверждает ни одну из перечисленных частей и не включает
МТС Линк в приложение.
